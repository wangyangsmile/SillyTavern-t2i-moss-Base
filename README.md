# MOSS 插画（本地 ComfyUI）

> SillyTavern 扩展 · 版本 **1.0**
> 仓库：`SillyTavern-t2i-moss-Base`

SillyTavern 第三方扩展。**每一轮 AI 回复时，让它顺手把这一轮的画面写成提示词**，
前端把提示词藏起来，只留一个短标题和一个「生图」按钮 —— 你点哪张，才画哪张。
出图走本机 ComfyUI，不经过任何在线绘图服务。

- 从角色卡 `AV制作大亨` 里那套「小手机生图」模块移植，保留你要的几块：
  **正文提取并生成提示词、场景类型解析、生图、工作流导入与选择、相册**
- 去掉了全部 NAI / NovelAI 逻辑，也去掉了内置的 IL / Pony / SDXL / Flux 预设工作流
- 配图块的输出格式与写法，参考了 Grok 那套世界书，并针对 MOSS 重做（见「配世界书」）

**想改代码或二次开发**，请看 [DEVELOPER.md](DEVELOPER.md)。

## 安装

```bash
cd <SillyTavern>/public/scripts/extensions/third-party/
git clone https://github.com/wangyangsmile/SillyTavern-t2i-moss-Base.git st-moss-image
```

或者直接把整个目录拷到：

```
<SillyTavern>/public/scripts/extensions/third-party/st-moss-image/
```

刷新酒馆页面，在「扩展」抽屉里就能看到 **MOSS 插画 · 本地 ComfyUI**。

前提：ComfyUI 已启动（默认 `http://127.0.0.1:8188`），并且有 MOSS 的模型和 LoRA。

## 它是怎么工作的

```
AI 回复  ──►  正文里夹着配图块：
                 <photo title="窗边的午后" kind="scene">午后的光斜着落在木桌上……</photo>
                        │
        ┌───────────────┴────────────────┐
        │ 酒馆渲染（标签被摊成普通正文）  │
        └───────────────┬────────────────┘
                        ▼
        扩展按「提示词原文」精确找到那段文字，整段换成一张小卡片：

                 ┌──────────────────────┐
                 │ 窗边的午后   [ 生图 ] │
                 └──────────────────────┘

        点按钮 ──► 排队 ──► ComfyUI ──► 卡片原位变成图
```

三个要点：

1. **聊天记录里的提示词原文一个字都不改**。模型下一轮还看得见上一轮写了什么，
   人物的发色、配饰这些「视觉锚点」才能跨轮对得上。藏起来的只是前端的显示。
2. **不点就不画**。默认模式下 4 块配图就是 4 个按钮，你可以只点想看的那一张，
   剩下的留着不占显卡。
3. **每块有自己的位置**。出图后图会落在它原来那一块的位置，不会被堆到消息末尾。

## 三种模式

设置里「正文里的配图块怎么处理」：

| 模式 | 行为 | 适合 |
|---|---|---|
| **显示成卡片，点了才画**（默认） | 只显示标题和「生图」按钮，点一下才开始排队 | 想自己挑画面，也不想一回合跑满四张 |
| **直接开画** | 每块立刻排队生成，不点 | 显卡闲着，想一次看全 |
| **什么都不做** | 不理会配图块，只用每条消息上的小魔杖按钮手动出图 | 调试、或者只想手动 |

配图块之外的正文照常显示。`<UpdateVariable>` 这类别的扩展要用的控制标签，插件**不会**动。

## 配图块怎么写给 AI

推荐写法（**一行写完，标题放属性里**）：

```
<photo title="窗边的午后" kind="scene">午后的光斜着落在木桌上，她托着腮看向窗外，神情安静。</photo>
```

- `title` 是卡片上显示的那几个字，6～12 个中文字最好
- `kind` 三选一：`selfie`（人物近景/生活照，默认）、`scene`（场景为主，取景宽）、`private`（私密空间）
- 标签里放**中文画面描述**，不是 tag 串

为什么必须一行？酒馆的 Markdown 渲染器遇到多行标签会拆成一堆 `<p>` 和 `<br>`，
插件还得自己拼回去；单行属性写法渲染完就是干干净净的一个 `<p>`，整段替换最稳。

也兼容这些老写法（别处抄来的卡可能用得上）：

```
<photo>【标题】image###提示词###</photo>         ← Grok 的格式
<photo>标题｜提示词</photo>                      ← 简写
<photo>1girl, solo, smile</photo>                ← 纯标签
<photo title="标题" prompt="提示词" />            ← 自闭合
```

## 配世界书（重要）

只装插件、不告诉 AI 怎么写配图块，是什么都画不出来的。同一目录下的
**`MOSS配图世界书.json`** 就是干这个的，在酒馆「世界信息」里导入，
再挂到对应的角色卡上。

它一共 5 个条目：

| 条目 | 作用 | 默认 |
|---|---|---|
| `MOSS配图` | 主条目：每轮 3 张剧情图 + 1 张彩蛋，写在哪、怎么写、视觉锚点规则 | 开启 |
| `DLC-人像写真` | 追加人像棚拍质感（柔光、皮肤、浅景深） | 关闭 |
| `DLC-写实摄影` | 追加中文摄影语言（焦段、景深、光线），按场景挑一种 | 关闭 |
| `DLC-胶片电影感` | 追加胶片质感与宽画幅构图思路 | 关闭 |
| `DLC-动漫插画` | 把写实质感换成日系动画语言 | 关闭 |

四个 DLC 互不冲突但别同时开 —— 它们都往提示词末尾追加风格句，开多了会互相拉扯。
想用哪个就只开哪个。

**视觉锚点**是这套东西真正的价值，值得单独说：角色第一次出现在画面里时，
让 AI 固定一组外貌描述（年龄段、体型、发色发型发长、面部特征、肤色、固定配饰、辨识标记），
之后每张图都**整句原样**抄进去，不许换近义词、不许因为远景就省掉。这样同一个人才不会每张图换张脸。
`{{user}}` 没设定过外貌时，规则是只拍背影、手、过肩镜头，不凭空捏一张脸。

## 提示词从哪来

如果 AI 已经在配图块里写好了画面描述，**就用它写的，不二次加工** —— 这是最准的来源。

配图块没写、或者用消息上的手动按钮时，才走设置里「提示词怎么来」：

- **当前对话模型解析正文**（默认） —— 用酒馆的静默生成，让模型把这一轮正文写成一段画面描述。
  提示词是中文的，因为 MOSS 的文本编码器是 qwen3.5：实测中文散文出图更贴、更实，
  逗号堆出来的英文 tag 串反而会被忽略风格词、还会凭空加眼镜之类的东西。
- **离线词典** —— 纯本地，150 多条中文场景词到 danbooru 标签的映射。快、不耗 token，但词汇量有限。
- **只用配图块里的内容** —— 完全信任 AI，缺了就报错，不做兜底。

最终提示词 = 前缀 + 身份词 + 画面描述 + 后缀。
**身份词用来固定角色外观**（发色、瞳色、体型），是跨轮保持一致最省事的办法。
中文描述用全角逗号接，英文标签用西文逗号接，不会把中文句子切碎。

## 工作流

设置里「导入 JSON」可以放任意 ComfyUI 的 API 格式工作流（ComfyUI 设置里勾 Enable Dev mode Options，
菜单 Workflow → Export (API)）。导入后面板会显示识别结果：节点数、模型、尺寸、采样参数、
正面/负面提示词节点，以及需要注意的地方。

内置的 MOSS 工作流有四个特点，面板会照实标出来：

1. **负面是 `ConditioningZeroOut`** —— 这套工作流根本不吃负面词，填了也不会生效
2. **尺寸 1080×1920 会被对齐到 1088** —— 潜空间要求 16 的倍数，实际出图比参数宽 8 像素
3. **双 LoRA 写死在 37、38 号节点里** —— 想换 LoRA 要改工作流，UI 里没有开关
4. **8 步 / cfg 1 / euler / simple** —— 模型自身设定，别随手调大

默认只覆盖正面提示词、种子和尺寸；模型、采样参数、负面词这三个要显式打开「覆盖」才会动。

实测 4070 上一张 1088×1920 大约 30 秒。

## 图片存在哪

- 图片本体（Blob）存在浏览器的 IndexedDB（库名 `st-moss-image`），**不进聊天记录文件**，
  不会把聊天存档撑爆
- 聊天记录里只留一小段元数据，存在消息的 `extra.mossImages` 里：
  `{id, prompt, seed, width, height, kind, createdAt, workflow, from, slot, title}`
  其中 `slot` 是它是这一楼第几块配图（0 开始），`title` 是卡片标题 —— 靠这两个才能把图贴回原位
- 消息重绘、切聊天、刷新页面时，按元数据从 IndexedDB 把图重新贴回对应的槽位
- 设置面板底部会显示当前占用了多少空间，可以按当前聊天清空或全部清空

点图片本身有灯箱；图下方「换一张」用同一段提示词换个种子重画，「下载」存原图。

## 一个必须知道的坑：首次连接很慢

浏览器对 ComfyUI 那个端口的**第一条连接**，在这台机器上要等 9～70 秒（实测多次，
用 curl 打同一个地址只要 4 毫秒，换个干净配置的浏览器也一样）。连上之后所有请求都是个位数毫秒。

所以：

- 扩展启动时会先发一条最轻的请求把连接焐热，面板上的状态会显示已经等了多少秒
- 连接检查给足 120 秒，**不会**超时就重试 —— 中途 abort 等于重新开一条冷连接，只会更慢
- 第一次出图如果卡在「准备中」，多半是在等这条连接，不是坏了

## 自测

仓库里只放运行所需的文件，测试脚本不在其中（避免把调试用的截图和浏览器自动化带进发行版）。
改完代码之后，最低限度的验证顺序是：

1. 打开酒馆，F12 看控制台有没有 `[moss] 扩展已加载`
2. 扩展抽屉里面板能出来、状态显示连上了 ComfyUI
3. 找一条带配图块的消息，确认只显示「标题 + 生图」，点一张能出图
4. 刷新页面，图还在原位 —— 这一步能发现 90% 的槽位写错问题

写自动化的话，两条纪律（血泪）：

- **别在脚本里主动导航页面**。这台机器上酒馆首屏要几十秒才响应渲染进程，
  带导航的用例会假失败；用 `Page.reload` 后轮询 `#chat` 和 `window.__moss` 出现即可。
- **求值只用短超时轮询**。别写长超时的 `Runtime.evaluate`，会挂死在一次求值上，
  最后什么信息都拿不到。

`window.__moss` 留了调试口子：`__moss.handleMessage(mesId)`、`__moss.attachAll()`、
`__moss.settings()`、`__moss.state`、`__moss.queue`。
